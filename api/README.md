# REST API payment-processor

> **Язык / Language:** Русский | [English](i18n/en/README.md)

Контракт REST API между `payment-processor` и Android-приложением кассира `mobile-dashboard`. Спецификация: [`openapi.yaml`](openapi.yaml) (OpenAPI 3.1). Swagger UI поднимается в Docker Compose: http://localhost:8089.

REST только читает данные. Транзакции создают терминалы через Kafka, формат сообщений описан в [docs/kafka](../docs/kafka/README.md).

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/v1/transactions` | История операций с фильтрами и курсорной пагинацией |
| GET | `/v1/transactions/{transaction_id}` | Статус одной транзакции |
| GET | `/v1/transactions/stream` | Обновления в реальном времени (SSE) |
| GET | `/v1/terminals` | Известные терминалы, для фильтра в приложении |
| GET | `/healthz` | Проверка живости, без токена |

## Принятые решения

- **Модель `Transaction`** использует те же имена и форматы полей, что Kafka-контракт: `transaction_id` (UUIDv7), `terminal_id`, `amount_minor`, `currency`, `reason`, время в RFC 3339 UTC с миллисекундами. В REST добавлен статус `pending`: в Kafka он не публикуется, но кассиру нужно видеть платёж в обработке.
- **Реальное время: SSE.** Поток идёт только от сервера к клиенту, реализация проще WebSocket. Каждое изменение статуса приходит событием `transaction.updated` с телом `Transaction`. После обрыва клиент переподключается с заголовком `Last-Event-ID`, сервер досылает пропущенное. Если досылать уже нечего, сервер сначала шлёт событие `resync`: клиент перечитывает историю через `GET /v1/transactions`. Каждые 15 секунд сервер шлёт keep-alive. Экземпляров processor может быть несколько, события между ними раздаются через Redis pub/sub.
- **Аутентификация:** статический Bearer-токен, общий для приложений кассиров и заданный в конфигурации processor. Это защита уровня прототипа: нет учётных записей и ротации токена. Токен нужен всем эндпоинтам, кроме `/healthz`. SSE-клиент должен уметь задавать заголовки (например, OkHttp-sse).
- **Область видимости:** кассир видит транзакции всех терминалов, фильтр `terminal_id` необязателен.
- **Фильтры истории:** поддерживаются терминал, один или несколько `status`, префикс `transaction_id`, диапазон `amount_minor`, валюта, причина ошибки и полуинтервал времени `from <= created_at < to`. Все фильтры необязательны и объединяются через AND; несколько статусов объединяются через OR. `max_amount_minor` не может быть меньше `min_amount_minor`.
- **Пагинация:** курсорная, сначала новые. Порядок задаёт `transaction_id`: UUIDv7 упорядочен по времени создания. Курсор непрозрачный, берётся из `next_cursor`.
- **Ошибки:** формат RFC 9457 (`application/problem+json`) с устойчивым полем `code`: `invalid_parameter`, `unauthorized`, `not_found`, `internal_error`.
- **Коды `reason`:** список пока не зафиксирован, он общий с Kafka-контрактом (`pos.transaction-results.v1`).

## Версионирование

Версия API входит в путь (`/v1`). Несовместимые изменения выходят как `/v2`, добавление необязательных полей и эндпоинтов версию не меняет.
